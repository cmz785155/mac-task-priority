# Mac 任务优先级 · Mac Task Priority

轻量的 Apple Silicon Mac 菜单栏工具，手动提高指定进程的 CPU 调度优先级。原生 Swift / AppKit，无第三方运行时、网络请求或持续 CPU/GPU 性能采样。

**2.0.1 为公开测试版。** 已移除全部五种电源档位及 pmset 切换。请下载 [2.0.1 安装包](https://github.com/cmz785155/mac-power-modes/releases/tag/v2.0.1)；1.x 旧包仍是电源模式工具。

## 使用

点击菜单栏调节图标 → “选择应用或任务…” → 选择应用或输入工作进程 PID → 选择调度优先级 → 系统管理员授权。

- 提高：nice -5。
- 更高：nice -10。
- 每次最长 30 分钟；从“活动任务”子菜单单独恢复，或“结束全部并恢复”。
- 退出本软件后，临时监督进程恢复原值，通常在事件通知后发生；退回兼容轮询时约 1 秒内发生。

只作用于当前账户的指定进程，不调节其他应用、子进程或 GPU 调度。大模型/剪辑应用可能用后台进程计算，选应用主进程不一定影响实际工作进程；可从活动监视器确认 PID。

这是真实的 `setpriority` 调度设置，并回读确认。它不锁定频率、不超频、不解锁功耗上限，不保证加速。应用的 QoS、GPU、内存带宽或磁盘瓶颈可能主导表现；没有 CPU 争抢时可能没有速度收益。应使用相同任务的完成时间或吞吐量衡量收益。

软件不会关闭、暂停或重启用户应用和项目；不修改电源模式、风扇、睡眠、亮度、充电或温控。启动时不改变目标进程设置。

## 权限与低开销

每次开始需独立管理员授权。软件不读取或保存密码，不新增免密规则，不安装 LaunchDaemon。只有会话活动期间运行临时监督进程，使用 kqueue 等待进程退出、会话文件变更或一次性的到期超时，不进行每秒轮询。恢复前核对 UID、PID、启动时间及当前优先级；事件接口不可用时退回每秒检查，以保留恢复能力。任务状态直接通过 libproc/getpriority 读取，不启动辅助进程。

若其他工具改变优先级，保留外部修改；PID 被重用时不修改新进程。强制终止监督进程或系统故障可能使恢复失败，重启目标应用可获得新的默认调度。菜单关闭时不做性能采样；打开菜单及应用退出/唤醒事件触发会话回读。

从旧版升级时，可在“设置与说明”移除旧版电源免密规则，不改变已有电源策略。新版本完全不使用该规则；不存在旧规则时不显示迁移入口。

## 构建与检查

需要 Apple Silicon Mac、macOS 15.1+ 和 Xcode Command Line Tools。实际验证环境为 M4 Pro / macOS 27.0.1，其他版本未实机验证。

```sh
./scripts/build.sh
./scripts/test.sh
```

从上方发布页面下载 `MacTaskPriority-2.0.1-arm64.zip` 并解压，将 `Mac任务优先级.app` 拖入“应用程序”。源码构建输出为 `dist/release/Mac任务优先级.app`。目前使用临时签名，无 Developer ID 签名或 Apple 公证，首次启动可能被系统拦截。

普通检查验证进程身份读取、非法参数、拒绝自身目标和不支持的档位，不修改运行任务。构建产物的 `--self-test` 只读检查实时进程身份。

管理员集成测试只创建一次性测试进程，验证调节、到期、提前取消、应用退出恢复、外部修改保留及等待事件而非轮询：

```sh
sudo /usr/bin/python3 Tests/priority-session.py dist/release/Mac任务优先级.app/Contents/MacOS/priority-helper "$(id -u)"
```

该检查不证明实际工作任务加速。CPU/GPU 频率、功耗接口调查及 GitHub 参考实现见 [hardware-controls.md](docs/hardware-controls.md)。
